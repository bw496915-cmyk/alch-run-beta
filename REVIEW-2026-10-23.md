# Review — 2026-10-23: shape conformance, tool failures, task scoping

Three questions: does this repo match the **documented shapes** for beta.83, what actually
**failed** and why, and what should the parallel workers do next.

---

## 1. Shape check against the beta.84 post + docs

Re-read [the release post](https://alchemy.run/blog/2026-10-22-beta-84/) and the canonical
pages for [Durable Objects](https://alchemy.run/cloudflare/compute/durable-objects/) and
[Queues](https://alchemy.run/cloudflare/messaging/queues/).

| Concern | Documented shape | This repo | Verdict |
| --- | --- | --- | --- |
| Resource declaration | `Cloudflare.R2.Bucket("Id")`, `Cloudflare.D1.Database("Id", { migrations })`, `Cloudflare.KV.Namespace("Id")`, `Cloudflare.Queues.Queue("Id")` | identical | ✅ conformant |
| Worker | two styles sanctioned: async `Cloudflare.Worker("id", { main, env })` **or** Effect-native `Cloudflare.Worker("id", { main: import.meta.url }, Effect.gen(...))` | async style, `main: "./src/Api.ts"` | ✅ sanctioned style |
| Bindings into the async worker | `env: { K: resource }` — docs note "`env` is the only option for async (non-Effect) Workers" | `env: { PHOTOS, DB, CACHE, EVENTS, COUNTER }` | ✅ conformant |
| Durable Object binding | plain-class form is documented: `env: { AGENT: Cloudflare.DurableObject("Agent", { containers: [...] }) }`, explicitly "only for a plain (async) Durable Object class the Worker hosts" | `COUNTER: Cloudflare.DurableObject("Counter", { className: "Counter" })` | ✅ conformant (plain class in `src/Api.ts`) |
| Durable Object class | **documented example** is Effect-native: `export default class Counter extends Cloudflare.DurableObject<Counter>()("Counter", Effect.gen(...))` | plain class, `constructor(state, env)` + `fetch()` | ⚠️ supported but *undocumented as an example*; the DO is the piece that threw a transient 1101 |
| Queue consumer | **documented** as `Cloudflare.Queues.consumeQueueMessages(queue, stream => …)` + `EventSourceLive`, or the `Queues.Consumer` resource with `scriptName: worker.workerName` (d.ts docs, "What's the difference vs a native `queue()` handler?") | `Queues.Consumer` + plain `async queue(batch, env)` | ✅ proven live (audit row written by the consumer) |
| Cron | **documented only** as `Cloudflare.Workers.cron("* * * * *", handler)` + `CronEventSourceLive` (Effect-native) | `crons: ["0 3 * * *"]` prop + plain `async scheduled(...)` | ⚠️ prop exists in `WorkerProps`, but **not documented for async workers — and it did not fire in production** |

**Conclusion:** the "correct shape" is ambiguous only for the two pieces that misbehaved —
**DO class style** and **cron declaration**. Every successful piece (R2/D1/KV/Queue/bindings/
async worker) matches a documented shape. The two unproven pieces are exactly the ones the
docs only show in Effect-native form. That is the leading hypothesis for both bugs, and it
is what subagent **A** and **B** must settle empirically rather than by argument.

## 3. Scoping for parallel workers

Five independent tracks. A and B both touch the live account, so they are pinned to
**separate stages** and told to destroy their stages; `deep-pass` is owned by **A** only,
which must restore the committed daily cron as its last act.

| Track | Owner | Writes live infra? | Deliverable |
| --- | --- | --- | --- |
| **A. Cron root cause + fix** | subagent | yes — own stage `cron-probe`; repairs `deep-pass` cron | root cause, minimal fix, observed cron fire, daily cron restored |
| **B. DO 1101 root cause** | subagent | yes — own stage `do-probe` | reproduction, shape comparison (plain class vs `extends DurableObject`, redeploy-without-migration), recommended change |
| **C. Shape conformance audit** | subagent | no (read-only) | per-file conformance table with citations, ranked deviations, minimal diffs |
| **D. Test harness + CI gate** | subagent | no | `alchemy/Test` integration test + GitHub Actions workflow (typecheck always; deploy gated) |
| **E. Failure/README record** | subagent | no | `FAILURES.md` from §2 + README revision matrix update |

Coordination rules given to every worker:

- Never run `destroy` against `deep-pass`; only the stage you own.
- `pnpm typecheck` must stay green; `git` commits only for docs/tests, never `alchemy.run.ts`
  without stating the change.
- Credentials live in `.cf-token` (gitignored) — read it, never print it, never commit it.
- Report command output verbatim rather than conclusions.

## 4. Layers we are missing (ranked), found by re-reading the docs rather than the code

Each item is a *documented* capability this repo does not use. Ordered by how much it would
have prevented the pain we already hit.

| # | Layer | What the docs say | Why it matters here | Blocked by |
| --- | --- | --- | --- | --- |
| 1 | **Typed `env` via `Cloudflare.InferEnv`** | async-worker pattern is `export const Worker = Cloudflare.Worker("Worker", { main, env })` then `export type WorkerEnv = Cloudflare.InferEnv<typeof Worker>`, and the worker file does `import type { WorkerEnv } from "../alchemy.run.ts"` ([secrets docs](https://alchemy.run/environments/secrets/), `Cloudflare/Workers/InferEnv.d.ts`) | we hand-wrote ~90 lines of structural interfaces, which is why a `1101` on a DO call produced no type error and why track C has a typing-deviation list to audit | track C's report, then a refactor of `alchemy.run.ts` + `src/Api.ts` |
| 2 | **Secrets binding** | `env: { API_KEY: Config.Redacted("API_KEY"), HOST: Config.String("HOST") }`, plus the documented footgun: never `yield* Config` in the runtime effect (nothing gets bound) | we deploy zero secrets; `/stats`, `/audit` are unauthenticated on a public `workers.dev` URL | nothing — needs a decision on which secret to bind |
| 3 | **`RemovalPolicy`** | `RemovalPolicy.retain()` / `.destroy()` on resources (`RemovalPolicy.d.ts` exports both) | every resource currently takes the default policy, so a rename or an accidental removal is one `destroy` away from deleting the D1 database and R2 bucket | nothing |
| 4 | **`deadLetterQueue` on the queue consumer** | `ConsumerProps.deadLetterQueue?: string` (`Cloudflare/Queues/Consumer.d.ts`) | our consumer retries 3× then drops the message — a poison audit event vanishes silently | nothing |
| 5 | **Degradation instead of 500** | n/a — engineering hygiene | the transient DO `1101` turned the whole `/stats` endpoint into a 500; a `try`/`catch` around the DO call would have returned `{durableObject: null, d1: {...}}` and the bug would have been visible instead of fatal | tracks A/B (they own those files) |
| 6 | **Ops commands: `drift`, `check-env`, `logs`** | all three exist in the pinned CLI | we never ran drift once, so "plan says noop" is the only idempotency evidence we have | **done** — wired into `scripts/alch.sh` |
| 7 | **Alchemy's own test harness** | `alchemy/Test/Vitest` + `alchemy/Test/TestState` (in-memory state) — deploy/destroy around a real stack, and seeded state without a cloud | track D builds offline fakes instead; the documented harness is the integration half that proves the *deployment*, not just the handlers | track D's report |
| 8 | **Remote state store for CI** | `state: Cloudflare.state()` + one-time bootstrap (beta.83 form is `alchemy provider cloudflare bootstrap`, **not** `alchemy state bootstrap`) | local state means only this checkout can update or destroy the stage | **done** — documented in `MIGRATION-beta84.md` |
| 9 | **`alchemy/Workflows`** | durable workflows on DO / Cloudflare Workflows / Lambda durable functions (post, "Effect workflows on every engine") | the largest documented feature we have not touched; the natural home for "reindex after upload" instead of a bare queue consumer | nothing (biggest scope) |
